# Лаунчер

Electron + библиотеки @xmcl (установка NeoForge, загрузка файлов Mojang, запуск).
Пиратский: офлайн-ники, без входа в аккаунт.

Репозиторий лежит в папке `launcher/` проекта карты. Сам проект карты
(`pack/`, мир, документы) в Git не хранится: скрипты сборки ищут его
уровнем выше, в `../pack`.

## Запуск для разработки

Нужен [Node.js](https://nodejs.org) LTS (22 или новее).

```powershell
cd launcher
npm.cmd install      # один раз и после изменения package.json
npm.cmd start        # открыть лаунчер
```

В PowerShell пишите `npm.cmd`, а не `npm`: обычный `npm` там блокируется политикой скриптов.

Настройки игрока (ник) лежат в `%APPDATA%\MOP Launcher\settings.json`.
Удалите файл, чтобы снова увидеть первый запуск.

## Где лежит игра

```
%APPDATA%\MOP Launcher\
  settings.json          ник
  state.json             что уже установлено
  java\                  Java от Mojang (та же, что у официального лаунчера)
  game\                  общие файлы: versions, libraries, assets
  instances\mop2\        папка игры карты: mods, config, saves, logs
```

Если в пути к `%APPDATA%` есть русские буквы (имя пользователя Windows кириллицей),
игра ставится в `C:\Users\Public\MOP Launcher`: Minecraft плохо переносит такие пути.
Ник остаётся в `%APPDATA%`.

Проверка установки и запуска из консоли, без окна (то же, что делает кнопка, но с подробным выводом):

```powershell
npm.cmd run try:install
npm.cmd run try:launch -- Freddy_42
```

Чтобы установить всё заново, удалите `state.json` (или всю папку `MOP Launcher`).

## Установщик

```powershell
cd launcher
npm.cmd run dist     # release/MOP-Launcher-Setup-<версия>.exe
```

- Установщик в один клик, без прав администратора: ставит лаунчер в `%LOCALAPPDATA%\Programs`,
  делает ярлыки на рабочем столе и в «Пуске» и сразу открывает лаунчер. Удаление через
  «Приложения» Windows; игра и ник в `%APPDATA%\MOP Launcher` при этом остаются.
- Внутрь кладётся `dist-pack/` (манифест, `.mrpack`, обложка, мир): сразу после установки
  карта уже в списке, даже без релиза в GitHub. Поэтому перед `dist` выполните `pack:build`,
  без `dist-pack/manifest.json` сборка остановится.
- Установщик не подписан, поэтому Windows покажет «Windows защитил ваш компьютер»:
  «Подробнее» → «Выполнить в любом случае».
- Версия установщика берётся из `version` в `package.json`.

## Иконка и музыка

- Иконка: `build/icon.svg`. После правки выполните `npm.cmd run icon`: получатся `build/icon.png`
  и `build/icon.ico` (её берёт сборка .exe; свой конвертер electron-builder на некоторых ПК падает
  с «WebAssembly.Memory(): could not allocate memory»).
- Музыка: `src/renderer/assets/music.ogg` играет по кругу без паузы на стыке и затихает, пока идёт игра.
  Кнопка в шапке выключает её, выбор запоминается. Трек — тёмная колыбельная на 80 секунд
  (пэд Am–F–Dm–E, расстроенная музыкальная шкатулка, далёкие удары по трубам), синтезирована
  скриптом `media/launcher-music/make-music.js` проекта карты. Поправить: изменить скрипт,
  `node make-music.js`, `ffmpeg -i music.wav -c:a libvorbis -q:a 5 music.ogg`, скопировать сюда.
  Без файла лаунчер просто молчит.

## Сборка карты (.mrpack)

Сборка игрока выходит в формате Modrinth (`.mrpack`): моды, шейдер и PBR-пак
внутри не лежат, это ссылки на Modrinth с sha1/sha512, а наши файлы
(kubejs, конфиги, ресурспак `mop2-resources`, профиль шейдера) лежат в `overrides/`.
Тот же файл импортируется в Prism Launcher, это запасной вариант для демо.

```powershell
cd launcher
npm.cmd run pack:lock    # дописать в pack/modlist.lock.json новые записи из modlist.json и хеши sha512
npm.cmd run pack:build   # собрать launcher/dist-pack/
```

В `launcher/dist-pack/` появляются `mop2-<версия>.mrpack`, `mop2-cover.png`
и `manifest.json`. Всё это загружается в один релиз GitHub.

- Название, описание, версия карты и версия NeoForge хранятся в `pack/pack.json`.
- Обложка лежит в `pack/cover.png` (16:9, например 1280×720). Сейчас там временная.
- `pack:lock` не трогает уже закреплённые версии. Обновить всё до свежих версий
  можно через `tools/sync-mods.ps1 -Update`.

## Мир

Положите мир в `world/` проекта карты (`level.dat` прямо в ней или в одной вложенной папке)
и выполните `npm.cmd run pack:build`: появится `mop2-world.zip`, а в манифесте поле `world`.
Папка мира в `saves/` задаётся в `pack/pack.json` → `world.folder` (сейчас `MOP2`).

- Мир ставится один раз. Если папка уже есть, лаунчер её не трогает: чекпоинты игрока лежат внутри мира.
- Новая версия карты обновляет датапак `mop2` (он едет в сборке и кладётся внутрь мира), но не сам мир.
- Чтобы игрок получил мир заново, ему надо удалить папку `instances\mop2\saves\MOP2`.
- В архив не попадают `playerdata`, `stats`, `advancements`, `session.lock` и датапак `mop2`.
- Кнопка «Играть» входит сразу в мир (`--quickPlaySingleplayer`), мимо главного меню.

## Настройки игры и графика

Настройки, которые лаунчер ставит в игру, лежат в `pack/graphics.json` проекта карты:

- `common` — русский язык, полный экран, FOV, яркость, ресурспаки, выключенная музыка Minecraft и т. п.
  Пишутся в `options.txt` один раз и снова только если блок поменяли в новой версии карты:
  что игрок сам поменял в игре, остаётся. Клавиши лаунчер не трогает.
- `levels` — три уровня графики (`low`, `medium`, `high`), выбираются на странице игры.
  У каждого: настройки Minecraft (`options`), Sodium (`sodium`) и шейдера (`shader`).
  Профиль шейдера = наш вид из `pack/shaderpacks/Solas_MOP2_profile.txt` плюс опции уровня поверх
  («Высокая» — профиль как есть). Уровень пишется при выборе другого и при его изменении в новой версии карты.
- Сборка (`pack:build`) превращает файл в `mop-graphics.json` внутри .mrpack; применяет его
  `src/main/graphics.js` перед каждым запуском. Для Prism в .mrpack лежат `options.txt` и профиль шейдера
  уровня по умолчанию.
- FOV в `options.txt` хранится как (FOV − 70) / 40: 0.125 = 75.

## Совместная игра

- Хост жмёт «Играть», в игре Esc → «Открыть для сети» и запускает. Мод e4mc выдаёт адрес вида
  `abc-def.e4mc.link`, лаунчер находит его в выводе игры (строка `Domain assigned: …`)
  и показывает на странице игры с кнопкой «Копировать».
- Друг жмёт «Присоединиться к другу» и вставляет адрес. Игра запускается сразу на сервер
  (`--quickPlayMultiplayer`), последний адрес запоминается в `settings.json`.
- У всех офлайн-ники, а сервер «Открыть для сети» по умолчанию проверяет их у Mojang
  («недействительная сессия»). Перед каждым запуском мира лаунчер пишет в
  `saves/<мир>/mcwifipnp.json` `"online-mode": false`, и экран мода mcwifipnp уже стоит на Online Mode → Disable.
  Если хост играет не в мире карты (мира в манифесте ещё нет), Disable надо выбрать руками.

## Манифест

В `config.json` два поля:

- `"manifest"` — ссылка на манифест последнего релиза GitHub (или путь к файлу, тогда берётся только он);
- `"bundled"` — манифест, вшитый в установщик (`dist-pack/manifest.json`).

Порядок: ссылка → копия с прошлой удачной загрузки → вшитый. Пока релиза нет (ссылка отвечает 404),
лаунчер показывает вшитую карту; после первого релиза новые версии подтягиваются сами,
переустанавливать лаунчер не нужно. В разработке (`npm.cmd start`) вшитым считается `launcher/dist-pack/`.

Ссылки внутри манифеста могут быть относительными: лаунчер считает их от адреса манифеста,
поэтому файлы просто должны лежать в том же релизе.

```json
{
  "formatVersion": 1,
  "maps": [{
    "id": "mop2",
    "title": "Mystery Of Pizzaplex",
    "subtitle": "Глава 2 — The Dark Corners",
    "description": "Абзацы через пустую строку",
    "players": "1–5 игроков",
    "tags": ["Хоррор", "Головоломки", "Кооп"],
    "version": "0.1.0",
    "minecraft": "1.21.1",
    "neoforge": "21.1.252",
    "cover": "mop2-cover.png",
    "pack": { "url": "mop2-0.1.0.mrpack", "sha1": "…", "size": 7556 },
    "world": null
  }]
}
```

## Устройство

```
launcher/
  config.json          откуда брать манифест
  dev-manifest.json    манифест для разработки
  scripts/             сборка карты (lock.js, build-pack.js), проверки из консоли (try-*.js)
  src/main/            «мотор»: окно, настройки, манифест, установка и запуск (game.js), графика (graphics.js)
  src/preload.js       мост между интерфейсом и «мотором» (window.mop)
  src/renderer/        интерфейс: index.html, style.css, app.js, assets/ (фон, музыка)
  build/               иконка (icon.svg и icon.png из неё)
  scripts/dist.js      сборка установщика, scripts/make-icon.js — иконка
```

## Библиотеки

`@xmcl/installer` закреплён на 6.1.2, `@xmcl/core` на 2.15.1. Более новые версии
(installer 6.3.x) на npm сейчас не ставятся: их зависимость `@xmcl/unzip` 2.2.0
опубликована битой. Обновлять, когда выйдет исправленная `@xmcl/unzip`.
